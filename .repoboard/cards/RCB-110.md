Owner, 2026-09-22: 'we also should cover if a system has test coverage.'

Open design question (owner decides; a card ask follows when a builder picks this up):
A. Static, no tool run: for each pointer path, the test files (packages/*/test/**, *.test.ts) that import it or name it — a count and a list, derived live like backlinks, 0 B added to systems.yml. Cheap, honest, null when the pointer is not a source file.
B. Coverage-report driven: read a vitest coverage JSON if one exists and map file → % lines; a missing report is null, never a guess. Needs the coverage run wired into the gate first.
C. A hand field tests: [...] on the row with provenance, like pointers. Simplest, but a convention nobody maintains.

Recommendation: A first (measurable today on both dogfood repos), B behind it as a second source with its own provenance. Surface: one line in systems show and get_system ('tests: 3 files'), a row in the Flow drawer, null / 'no tests found' when none. Conventions: a missing answer is null; every value carries where it came from.
