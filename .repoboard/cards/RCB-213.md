## Notes
- 2026-10-03T21:37:07Z builder — Measured 2026-10-03 in a scratch bare repo (removed after): pushing a NEW branch whose commits all sat under a second remote's tracking refs was ACCEPTED, while the same commits pushed where no remote had them carried 106 matching message lines and 985 matching added diff lines; the tip tree was clean, so the tree scan passed too. Control: pushing the clean single-commit main was accepted, and --tags was REFUSED (each tag's tree is scanned). Cause, scripts/public-guard.sh scan_push: for a new branch (remote sha all zeros or unknown) the outgoing range is `lsha --not --remotes`, i.e. commits absent from EVERY remote-tracking ref, not from the remote being pushed to; and content is scanned only as git grep over the tip tree, never over each outgoing commit's added lines, so a match added and later removed in history passes. Fix: take the remote name from the hook's $1 and use --not --remotes=<that remote>; scan added lines (git log -p over the range, + lines only, same excludes) of every outgoing commit. Tests in packages/server/test/public-guard.test.ts: (a) new branch whose commits are on another remote's tracking ref is refused on a message hit; (b) a match added then removed in an outgoing commit is refused; each control watched failing first.
- 2026-10-03T22:22:43Z builder — Fixed (builder, 2026-10-03): a new branch's outgoing range is now what no tracking ref of the PUSHED-TO remote has (--remotes=<name>; no name, or a URL, scans every commit), and every line each outgoing commit adds is scanned through the same hunk walker as pre-commit, reported as 'commit <short> path:line' without the text. Measured: the old guard accepted a 334-commit history held under another remote's tracking refs (exit 0); the new one refuses it with 1,114 places (63 commit messages, 1,051 added lines in 116 commits). On git 2.54, --full-history and --diff-merges=first-parent each alone stop a TREESAME merge hiding its side branch (1 hit each; neither: 0), so the merge test pins the pair. Three new tests, each watched failing with its one fix line reverted (1 passed -> 1 failed, file read back, bash -n 0, restored identical).
