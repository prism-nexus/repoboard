## Notes
- 2026-10-05T18:53:08Z builder — Measured 2026-10-05 on a scratch board with the built CLI. log --as demo --title t2 '- a bullet' prints "repoboard log: Unknown option '- '." and the log usage block, exits 1, and writes nothing: the day's log held 2 blocks after 4 calls, both from the controls. card add '- dash title' fails the same way. An option VALUE that starts with a dash fails differently: seat demo --update '- dash body' and log --title '- dash title' print "Option '--update' argument is ambiguous" (resp. '--title'). Controls: the same calls with plain text log and create, exit 0; a -- before the text works today (log ... -- '- a bullet' logged; card add -- '- dash title' created). Cause: the one shared parse() wrapper (packages/server/src/cli.ts:556-562) calls node:util parseArgs with strict: true, which reads any argument starting with '-' as an option; 39 call sites go through it. A Markdown log body naturally starts with '- ', and a caller that pipes the output through tail sees only the last line ('run repoboard --help for every command') and can miss the exit 1; one log block was lost that way on 2026-10-05. Fix options, not chosen: (1) in parse(), take an argument that starts with a dash then whitespace as text, positional or option value, since no option is spelled that way; (2) the refusal names the cure (put -- before the text, or use --stdin). Either needs a test per shape, positional and option value.
