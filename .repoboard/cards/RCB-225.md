## Spec
RCB-214 built `.github/workflows/release.yml` and rehearsed it (manual run 37160196446, green). The OIDC publish itself has never run, because npm has no trusted publisher registered for `repoboard`. 0.3.1 and 0.3.2 were published from a local machine with a granular token.

Facts this plan depends on (npm docs, docs.npmjs.com/trusted-publishers, read 2026-10-06):
- A new trusted-publisher configuration must make its first successful publish **within 2 days**, or it expires and can no longer be used or edited. So 0.3.3 has to be ready on `main`, version bumped but untagged, BEFORE step 2.
- npm >= 11.5.1, Node >= 22.14.0, `id-token: write`, GitHub-hosted runner. release.yml meets all four (npm floor enforced, `node-version: 24`, `ubuntu-latest`).
- `repository.url` in `packages/server/package.json` must match the GitHub repository exactly: it is `git+https://github.com/prism-nexus/repoboard.git`.
- Provenance is automatic for a public package from a public repo.
- An existing configuration cannot be edited, only deleted and recreated.

## Steps
1. **builder**: put 0.3.3 on `main`, untagged. Content: RCB-212 (the packed manifest's `workspace:*`) and RCB-210 (favicon), each with its gate, published via `scripts/publish.sh`. Then the version bump (`packages/server/package.json` and `src/version.ts`, CHANGELOG `[0.3.3]`, README Status) via publish.sh. Run a manual Release dispatch on main to check it is green: its dry run reaches `npm publish --dry-run` for an unpublished version.
2. **owner** (npmjs.com, account settings): the `repoboard` package > Settings > Trusted Publisher > GitHub Actions.
   - Organization or user: `prism-nexus`
   - Repository: `repoboard`
   - Workflow filename: `release.yml` (the filename only, no path)
   - Environment name: leave empty (release.yml uses no environment)
   - Allowed actions: `npm publish`

   Save, then tell the builder. The 2-day clock starts here.
3. **builder**: tag `v0.3.3` (annotated) on main's tip and push the tag. Watch the Release run. Done when it is green with the "Publish (tag push)" step a success, `npm view repoboard@0.3.3` shows the CI tarball's shasum, and the npm page shows provenance (`npm view repoboard@0.3.3 dist.attestations`). Create the GitHub Release from CHANGELOG `[0.3.3]`.
4. **owner** (npmjs.com): the `repoboard` package > Settings > Publishing access > "Require two-factor authentication and disallow tokens" > Update Package Settings. Only after step 3 is green: before it, this would block nothing that works and leave no fallback.
5. **owner** (npmjs.com > Access Tokens): revoke the granular token(s) used for 0.3.1 and 0.3.2. The 0.3.2 one was pasted into an agent session on 2026-10-05.
6. **builder**: CHANGELOG/README say releases publish from CI with provenance; RCB-214's "not yet measured: the OIDC publish" gets the measured run id. Card done.

If step 3's publish fails on OIDC: do NOT fall back to a token. Read the run's error, fix the workflow or have the owner delete and recreate the configuration (it cannot be edited), and re-run within the 2 days.
