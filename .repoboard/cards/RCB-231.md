## Problem

On a member board, the owner ran `repoboard archive` (2026-10-20). It `git mv`'d 172 done cards into
`.repoboard/archive/` and recorded nothing. There was no log block and no card Log line (archive never
rewrites a file), and no actor anywhere, even though the command takes `--as`. The renames sat
staged in a shared index for about 5 min, and no seat could tell whose they were. The board's
coordinator had to ask the owner in the log.

Owner, verbatim: "repobaord archive was done by me, that should be logged via repoboard as the app user if its not send it to the repoboard builder".

## Wanted

- A non-dry-run `archive` that moves ≥ 1 card appends ONE log block, attributed to the actor
  resolved as for every other command: `--as`, then `$REPOBOARD_ACTOR`, then `$USER`, then `cli`.
  The no-`$USER` exception that `log` has does not apply here. The block names the count, the cutoff,
  and the ids moved. A long list goes to a file that the block names (threshold to be set in the brief).
- `--dry-run` and a 0-card run write nothing (both are unchanged).
- If the log write fails, say so on stderr, and do not undo the moves.
- Help text and REFERENCE: the `archive` row says it logs.

## Commit: no (builder's call, 2026-10-20)

`archive` stays stage-only. repoboard never commits in a board's own repo: its one `git commit` is the
local layer's own repo. The caller owns that git. With the log block, the staged renames carry a
name and a list, which was the failure. An opt-in `--commit` can be a later card if anyone asks.
