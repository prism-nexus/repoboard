## Problem

Dependabot (advisories published 2026-10-22) flags `dompurify` 3.4.16, a direct dependency of
`packages/web`, bundled into the shipped dashboard. It is the sanitizer behind `renderMarkdown`
and `renderNote` (`packages/web/src/markdown.ts:7`). The first patched version is 3.4.17.

Read, not measured: our call is `DOMPurify.sanitize(html, { USE_PROFILES: { html: true } })`, which
returns a string with the default `text/html` parser. That meets none of the three preconditions:
IN_PLACE, SAFE_FOR_TEMPLATES with DOM or shadow-root output, or `application/xhtml+xml`. 0.3.3 on
npm ships 3.4.16 too.

## Want

- Bump to `^3.4.17`. The lockfile holds 3.4.17 or newer, and the rebuilt web bundle carries it.
- CHANGELOG `[0.3.4]` gets a Security line, and its date moves to the tag day.
- Gate, then publish this card and tag `v0.3.4` on main. main is already at 0.3.4 (PR #14), held
  untagged for this card on the owner's word, 2026-11-02.
- The other open alerts (vite, @vitest/mocker, undici; the MCP SDK and its body-parser/fast-uri/
  ip-address chain) are dev-only. The SDK is a devDependency, and `dist/cli.js` mentions none of
  them. Bump them in the same pass if the lockfile allows it, or say why not.
