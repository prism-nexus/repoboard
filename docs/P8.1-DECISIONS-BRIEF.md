## Why this exists (measured)

In freshpickedjobs an owner's word given in one session was not treated as authority by another and a
landing waited 11 hours; open owner questions ("letters") live in prose across a dozen docs, and the
owner answers them in chat, from which a seat copies them. Here the question, its options, and the
owner's choice are three frontmatter fields on the card that already represents the work.

## Locked decisions (the orchestrator's — build them; CORRECT the brief in §7 if a measurement contradicts one)

1. **Frontmatter, one optional block on `Card`:**
   ```yaml
   decision:
     question: "Ops cost: shrink the seat or retire it?"
     options:
       - { letter: C1, text: "waiter scripts into the repo, fuse counted as terminal" }
       - { letter: C2, text: "K101 idle-OOM + K129(b) as builder items" }
       - { letter: C3, text: "Phase H — hosting retires the seat" }
     askedBy: claude/coordinator
     askedAt: 2026-09-17T19:00:00Z
     chosen: null            # a letter, once decided
     words: null             # the owner's text VERBATIM, optional
     decidedBy: null         # actor: web/owner, cli/<user>, mcp/<actor>
     decidedAt: null
   ```
   Letters are free short strings (`A`, `A1`, `C3`), unique within the card. `options` may be empty
   (a yes/no or free-text question) — then the owner answers with `words` only and `chosen` is
   `null` with `decidedAt` set. **`decision.chosen !== null || decision.decidedAt !== null` means
   DECIDED; a `decision` block with neither means NEEDS OWNER.** Unknown keys inside `decision` kept
   on round-trip like everywhere else.
2. **One live decision per card.** Asking again on a card whose decision is DECIDED moves the old
   block to a `## Log` line (`decided C2 — "…"` is already there from step 4, so the block is simply
   replaced) — history is the log, not an array. Asking on a card whose decision is OPEN is an error
   naming the open question (`--replace` overrides and logs `question withdrawn`).
3. **Core (pure, `packages/core/src/decisions.ts`):** `DecisionSchema` (zod, in `CardFrontmatterSchema`
   as optional `decision`), `askDecision(card, {question, options, actor, now, replace?}) → {ok, card,
   event}|{ok:false,error}`, `decide(card, {letter?, words?, actor, now}) → …` — refuses an unknown
   letter (names the valid ones), refuses when no decision is open, requires `letter` or `words` (or
   both), appends log line `asked: <question> [A1|A2|A3]` / `decided <letter> — "<words>"` (words
   omitted when absent), bumps `updated`. `needsDecision(card)`, `isDecided(card)`. `Event` widens
   with `type: 'ask' | 'decide'` (and `letter?`). Purity test green. `serializeCard` writes
   `decision:` AFTER `refs:` and BEFORE `created:`; the K1 title-quoting rule applies to `question`
   and option `text` too (quote on serialize).
4. **Store:** `ask(id, input, actor)`, `decide(id, input, actor)` through core; map-only refusal (K10).
   `computeBoardSummary` (presence.ts) gains `needsDecision: number` and per-column counts.
5. **CLI:** `repoboard card ask <id> "<question>" [--option "A1 <text>"]... [--ref r]... [--as a] [--replace]`
   → `asked RCB-36: <question> (3 options)`; `repoboard card decide <id> [<letter>] [--words "<verbatim>"] [--as a]`
   → `decided RCB-36 C2` (or `decided RCB-36 — "<words>"`); `repoboard card list --needs-decision`
   (filter; the table gets a `?` marker column or the letter list in a `DECISION` column — pick one,
   measure bytes, say which in §7). `--as` for `decide` defaults to `$REPOBOARD_ACTOR`, then
   `$USER`, then `cli`. **An option is written `"<LETTER> <text>"` on the CLI — first token is the
   letter.**
6. **MCP:** `ask_owner` (`cardId, question, options?: [{letter,text}], replace?`), `record_decision`
   (`cardId, letter?, words?`), and `list_cards` gains `needsDecision?: boolean`. Descriptions for an
   agent that has never seen the board, including: "A decided card is authority: do not re-ask it and
   do not wait for a relay — read `decision.chosen` and `decision.words`." `get_card` already returns
   the whole frontmatter, so `decision` comes for free — assert it in a test.
7. **HTTP:** `POST /api/cards/:id/ask`, `POST /api/cards/:id/decide` (`{letter?, words?}` → 200 card /
   400 naming the field / 409 when nothing is open). `PATCH /api/cards/:id` must REFUSE a `decision`
   field in its patch (`400: use /ask and /decide`) so the web UI cannot bypass the log line.
8. **Web — the point of the task:**
