1. **`.repoboard/STATE.md`** — markdown, fixed H2 sections in this order: `## LIVE`, `## LAST LANDINGS`,

   appended. `repoboard state` prints the rendered page; `repoboard state --set-section LIVE --stdin`
   replaces one section's body and restamps line 3 (the only write surface besides an editor).
2. **`.repoboard/log/YYYY-MM-DD.md`** (UTC date). `repoboard log --as <seat> [--title "…"] (<text> |
   --stdin)` appends:
   ```
   ##### <SEAT-UPPERCASED> <ISO>: <title or first line>

   <text verbatim>

   ```
   creating the file with `# Log — YYYY-MM-DD` on line 1 if absent. Append-only: core exposes no
   rewrite. `repoboard log show [--date YYYY-MM-DD] [--seat s]` prints it.
3. **`repoboard init --practices`** — after the normal `init` (or on a repo that already has a board),
   creates if absent: `STATE.md` (sections with a one-line placeholder each, stamped now), today's log

   at the REPO ROOT** with exactly these eight lines (adapt paths to `.repoboard/`):

   3 read today's and yesterday's log · 4 read decided cards (`repoboard card list --json`, the `decision` block) before asking the owner
   anything — a decided card is authority · 5 the queue is the board (`repoboard card list --status todo`)
   · 6 write your block with `repoboard log --as <seat>` as you go · 7 rewrite STATE when you stand down
   · 8 `repoboard check` before you start and before you stop.

  log file exists yet) computed "today" via `new Date()` — the server's real wall clock — instead
  of the store's own (possibly test-injected) clock. Caught by the "WS snapshot carries state and
  today's log" test expecting `snap.log.date` to be `'2026-09-02'` (the fixture's fixed `NOW`) and
  getting `'2026-09-17'` (the actual sandbox date) instead. Fixed by adding a `get clock(): Date`

- **A third bug, in my own test, not the product**: the first version of "`GET /api/check?strict=1`

  30-minute active window), then tried to fix it up with a second `writeFile` on disk and hoped the
  running watched store would pick up the edit in time before the very next `fetch` — a real race
  (no `await` on the watcher's debounce). Fixed by writing the card with the correct `updated`
  timestamp from the start (same fix applied to the equivalent MCP test), removing the race
  entirely rather than adding a wait.
- **A real crash in the web layer, caught by the FULL suite going red the moment `StatePanel` was
  wired into `Board.tsx`** (24 of 50 web tests failed, `TypeError: storage?.getItem is not a
  function`, in every test that renders `<App>` at all): this sandbox's vitest environment exposes
  a `globalThis.localStorage` (Node's own experimental implementation, per the
  `--localstorage-file was provided without a valid path` warning printed on every run) whose

  is `false`, so the existence check other components in this repo already use (`safeLocalStorage`

  memory-backed `storage` override into the shared `Store`, but `StatePanel` reads the browser
  global directly (a collapsed/expanded panel is per-viewer UI state, not shared store state, per

  existence-check-only pattern already in this repo's own `store.ts` is not sufficient — left named

  own tests never exercise the real global (they always inject `storage`).
- **A gap in my own CLI test, found while running control C3** (see below): "append creates the day
