### Design decisions made while implementing (the brief leaves these to the builder)

- **`extractLinkedPaths`'s "looks like a path" rule**, since the brief names the RULE ("every
  repo-relative path named in backticks") but not the syntax test for "looks like a path". Landed
  on: the WHOLE backtick span must match `[A-Za-z0-9_.-/]+` (no spaces, quotes, `<>:*~()` — code
  snippets and prose fragments are excluded this way, not by a path/non-path heuristic), must not
  start with `/` (absolute), must have no path segment made ONLY of dots, and must contain either
  a `/` or a trailing `.ext` (1–6 alnum chars) — a bare word like `main`/`any`/`freshpickedjobs`
  is excluded (branch name / prose word, not a path) but `README.md` (no slash) is included. Every
  one of these rules was forced by a real span in freshpickedjobs' own CLAUDE.md (see the
  correction below), not invented in the abstract.
- **The `..`-guard generalised to "any segment made only of dots"**, not literally `..` alone.
  Measured: freshpickedjobs' real CLAUDE.md contains `` `.../job-seeker-pipeline` `` — a prose
  ellipsis abbreviating a path outside the repo, not a directory-traversal `..`, but syntactically
  the same "escape the repo" shape. A rule that only rejected literal `..` would have admitted
  this span (it contains no `/../` component) and then handed it to the server's
  `resolveRepoPath`, which does not recognise `...` as invalid either (it only rejects a `..`
  SEGMENT) — so without this generalisation the span would have reached a `stat()` call for a
  path that does not exist, silently doing nothing wrong today but for the wrong reason (luck: the
  path happens not to resolve to anything inside the repo, not because anything rejected it).
  Written up as a hand-checked exclusion in `packages/core/test/cost.test.ts`'s "excludes every
  other backticked span" test, not just folded silently into the extraction list.
- **`already` dedup across root/agents/linked**: if a repo's `CLAUDE.md` ever named its own path,
  or `AGENTS.md`'s, in backticks, the linked-paths pass in `gatherCost` skips it rather than
  double-billing the same bytes under two WHY categories. Not exercised by either real fixture
  (neither repo self-references), but a one-line guard against a plausible future one.
- **`cost`'s own exit code mirrors `check`'s cost-over-budget semantics** (exit 1 when CLAUDE.md
  is OVER, in both table and `--json` modes) — the brief's locked decision 2 says this for the
  finding but the CLI usage line doesn't spell out `cost`'s own exit code explicitly; treated the
  same OVER/OK boolean as the one truth both `check` and standalone `cost` report.
- **`costRoot`/`budgetFor` in `cli.ts`**: `cost` does NOT require `.repoboard/` to exist at all
  (unlike every other CLI command, which climbs via `requireRoot`) — `--root` measures ANY
  directory verbatim, and a bare `repoboard cost` still climbs to the nearest `.repoboard/` so it
  needs no flag inside a repoboard-managed repo. This was necessary, not optional: locked decision
  6's own worked example is `cost --root .../freshpickedjobs`, a repo with no `.repoboard/` at
  all — `requireRoot` would refuse it outright.

### Corrections to the brief, with the measurement that forced them

- **Locked decision 1's example WHY values ("root, linked from CLAUDE.md, agents") don't say
  whether `.claude/CLAUDE.md`/`CLAUDE.local.md` count as `root` too**, only that they're "listed
  separately". Since there are only three WHY values total and neither "agents" nor "linked from
  CLAUDE.md" describes a CLAUDE.md variant, they are `root`. Neither real fixture has these
  variants, so this is untested against real data — noted here rather than silently assumed.
- **The brief's "`CLAUDE.md <bytes> of budget <budget> OK|OVER`" line could be read as covering
  ALL CLAUDE.md variants summed.** Measured against the brief's own motivating story (fpj's
  CLAUDE.md specifically, cut from 32,620 B to 4,996 B) and locked decision 2's "Missing CLAUDE.md
  → the line says `CLAUDE.md — absent`" (singular, unambiguous for the plain root file): the
  budget line is about the ROOT `CLAUDE.md` alone. `.claude/CLAUDE.md`/`CLAUDE.local.md` are
  counted in `total` but never gate `over`.
- **The "Tests" section's `extractLinkedPaths` line says "ignores `..`, absolute, non-existent
  (existence is the server's filter…)" as one list**, which reads as if `extractLinkedPaths` itself
  ignores all three. It does not and should not (§0.5 — no filesystem access): it ignores `..` and
  absolute SYNTACTICALLY, and leaves "non-existent" alone entirely, for the server's `fileEntry` to
  filter. Split the tests accordingly — a core test named "keeps a syntactically valid relative
  path even when nothing on disk has that name" makes the boundary explicit rather than leaving it
  implied by what the test suite happens not to check.
- **No real bug found in the mechanism itself** — unlike P8.2/P8.3, no watcher race or silent-drop
  bug surfaced here, because `cost` has no watcher, no store event, and no persisted state; it is a
  pure read computed fresh on every call. The closest thing to a surprise was a MEASUREMENT, not a
  code defect (next section).

### The measurement that contradicts the brief's own framing (CLAUDE.md's "ask for measurements, not conclusions")

The brief's own justification is "freshpickedjobs' CLAUDE.md reached 32,620 B... it was cut to
4,996 B." Read as a success story, that implies the "cold context total" this tool measures should
now be small. **It is not: 2,536,728 B (≈634,182 tokens) — 85% of it is a single linked file,
`docs/HANDOFF.md` at 2,152,432 B**, because CLAUDE.md's own text backtick-references it ("the
running record") and this tool's rule is mechanical: every existing linked path counts the same
way, whether it means "read this every turn" or "consult this when you need the history." The
CLAUDE.md-specific budget (locked decision 2, which this tool implements literally) is UNAFFECTED
by this — 4,996 < 8,192 is still OK — but a reader who takes the `total` line as "what gets loaded
into context" would be badly misled by freshpickedjobs' own number. Written into `docs/AGENTS.md`
§11 as its own paragraph, not folded quietly into the measured table, because the DISTINCTION
(what the tool computes vs. what a human might assume it means) is the thing worth a future reader
knowing before they trust the `total` line at face value.
